# 개별 종목 차트 최근 1년 반영

- 요청일: 2026-10-19 (Asia/Seoul)
- 목표: 개별 페이지가 있는 모든 종목의 기본 차트를 최근 1년으로 표시하고, 실제 일봉 이력을 사용한다. 상장한 지 1년이 안 된 종목과 제공처 조회 실패는 별도로 기록한다.
- 처리 순서: 반도체 seed 등록 순서 → 피어 목록 등록 순서 → 캘린더의 시장·종목코드 순서. 중복 종목은 데이터 점검을 한 번만 수행하되 각 페이지 유형은 모두 확인한다.
- 다음 요청에서 이 문서와 `data/chart-audit/progress.json`을 먼저 읽고 미완료 항목부터 진행한다. 순차 수집 명령은 종목별 결과를 즉시 저장해야 하며 이미 확인한 종목을 다시 시작하지 않는다.

## 확인한 문제

1. 반도체 102종목은 약 2년의 일봉을 보유하지만 상세 페이지 기본 표시가 90일이다. 최장 버튼도 360일이므로 정확한 1년과 다르다.
2. 피어 상세(`/stocks/:ticker`)에는 자체 주가 그래프가 없다.
3. 일반 캘린더 상세(`/market-stocks/:ticker`)는 기본적으로 캘린더에 등장한 날의 가격만 표시한다. 연속 일봉이 아니므로 기간 표시만 늘려서는 요청을 충족하지 못한다.
4. 기존 Yahoo·TradingView 복원 캐시가 있으므로 우선 검증하여 재사용한다. 짧은 캘린더 기록을 1년 일봉으로 간주하거나 다른 거래소·통화의 이력을 섞지 않는다.

반도체 seed 순서, 피어 index 순서, 한국→미국→일본→대만→중국→유럽의 종목코드 순으로 전부 점검했다. **반도체 102종목, 피어 29종목은 모두 최근 1년 이력 확보를 확인했다.** 중복 종목은 합산 총계에서 한 번만 센다.

### 다음 요청에서 이어갈 작업

1. `progress.json`과 `pending.json`을 읽는다. 첫 미완료 종목은 **등록 순서 1,884번 BLFS (BioLife Solutions)**이다. 정상 확인한 13,584종목을 처음부터 다시 수집하지 않는다.
2. `python scripts/stock_chart_history.py repair --pending-only --limit 100`으로 남은 종목만 순서대로 재시도한다. 다른 PC에서는 압축 원본을 자동으로 로컬 SQLite에 복원하므로 작업 캐시가 없어도 재개할 수 있다.
3. 재시도만으로 해결되지 않으면 종목명 변경·상장 거래소·대체 자료원을 같은 상장 종목으로 확인한다. 다른 거래소의 가격을 임의로 붙이지 않는다.
4. BLFS와 CCO는 Yahoo `query1`/`query2`, 2년/5년/명시적 시작·종료 날짜 조회에서도 유효 종가가 한 건뿐이었다. 네이버 해외 주식 원본은 409 응답, 동일 종목 TradingView 일봉은 조회 실패였다. 실제 1년 이력이 확보되기 전에는 완료로 변경하지 않는다.
5. 보완 뒤 `audit` → `checkpoint` → `export` → `publish`를 실행하고 검증·배포한다. `checkpoint`는 종목별 최신 결과만 남기고 다음 미완료 순서를 갱신한다.

```powershell
python scripts/stock_chart_history.py repair --pending-only --limit 100
python scripts/stock_chart_history.py audit
python scripts/stock_chart_history.py checkpoint
python scripts/stock_chart_history.py export
python scripts/stock_chart_history.py publish
```
